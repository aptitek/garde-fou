# SQL, Zero-Downtime Migrations & Embedded Query Safety (`GF080`–`GF082`)

## Multi-Dialect Semantics, Online DDL & Parameterized Queries

- Write three-valued-logic-safe predicates (`IS NULL` / `IS NOT NULL` instead of `= NULL` or `!= NULL`, `SQL-NULL-COMPARISON`), prefer `NOT EXISTS` over nullable `NOT IN (SELECT ...)` (`SQL-NOT-IN-SUBQUERY`), bound every `UPDATE` and `DELETE` with a non-tautological `WHERE` clause (`SQL-UNBOUNDED-MUTATION`), and list explicit column names instead of `SELECT *` in views and application queries (`SQL-SELECT-STAR`).
- Keep PostgreSQL migrations zero-downtime: create and drop indexes `CONCURRENTLY` outside explicit `BEGIN ... COMMIT` blocks (`MIG-PG-CONCURRENT-INDEX`, `MIG-PG-CONCURRENTLY-IN-TX`), avoid volatile defaults or unvalidated `SET NOT NULL` / `FOREIGN KEY` / `CHECK` / `UNIQUE` constraints on existing tables (`MIG-PG-ADD-NOT-NULL-UNSAFE`, `MIG-PG-CONSTRAINT-NOT-VALID`), avoid table-rewriting `ALTER COLUMN TYPE` (`MIG-PG-ALTER-COLUMN-TYPE`), prefer `TEXT`/`VARCHAR` and `TIMESTAMPTZ` over `CHAR(n)` and `TIMESTAMP` (`MIG-PG-BAN-TYPES`), forbid explicit `BEGIN`/`COMMIT` in Cloudflare D1 migrations (`MIG-D1-FORBID-TRANSACTION`) and `AUTOINCREMENT` in SQLite/D1 (`MIG-SQLITE-AUTOINCREMENT-TRAP`), and keep migration version prefixes collision-free without destructive DDL (`MIG-DESTRUCTIVE-DDL`, `MIG-VERSION-COLLISION-OR-GAP`).
- Always pass query parameters out-of-band (`$1`, `?`, `%s` tuple args, `sqlx::query(...).bind(...)`, or tagged templates `` sql`...` ``) instead of interpolating strings (`format!`, f-strings, `${...}`, `+`) into SQL execution calls (`SQL-INJECTION-INTERPOLATION`), and never silence `squawk`, `sqruff`, or `sqlfluff` without a `>= 10`-character `-- <reason>` (`GF070`, `GF081`–`GF082`).
