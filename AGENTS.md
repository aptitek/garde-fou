# AGENTS.md — Inviolable Guardrails for Garde-fou

This repository implements **Garde-fou** (`garde` CLI binary), a polyglot static analyzer and governance orchestrator inspired by Pandoc's Hub-and-Spoke architecture (`Tree-sitter` -> `UAST` -> Pure rules + `SARIF` runners + `BLAKE3` cache).
The project enforces its own rules from the very first commit (**full dogfooding**).

---

## 1. Architecture: Functional Core, Imperative Shell

Crate boundaries are enforced by the compiler and architecture tests (`tests/architecture.rs`):

| Crate | Environment | Responsibility | Disk/Env/Process I/O | Console Output (`stdout`/`stderr`) |
| :--- | :--- | :--- | :--- | :--- |
| `gf-core` | `#![no_std]` + `alloc` | Pure algebraic types (`Span`, `RepoPath`, `Uast`, `Diagnostic`, `Config`, `Validation`) | Forbidden | Forbidden |
| `gf-rules` | `#![no_std]` + `alloc` | Pure static rule engine (depends **only** on `gf-core`) | Forbidden | Forbidden |
| `gf-parsers` | Pure `std` (no I/O) | Context detectors and `Tree-sitter` -> `Uast` bridges | Forbidden | Forbidden |
| `gf-engine` | Imperative Shell | `BLAKE3` cache, Git scope, `init` scaffolding, external `SARIF` runners | Allowed | Forbidden |
| `gf-cli` | `garde` Binary | CLI parsing (`clap`) and reporters (`human`, `agent`, `sarif`) | Allowed | Allowed **only** in `src/output.rs` |

- `gf-core` and `gf-rules` MUST preserve `#![no_std]` and `extern crate alloc;` at the top of `src/lib.rs` (`#[cfg(test)] extern crate std;` is permitted only for unit tests).
- No external dependency requiring `std` is permitted in `gf-core` or `gf-rules`.

## 2. Rust Quality (Edition 2024) — Zero Compromise

1. **Strictly forbidden constructs** (in production and tests alike):
   - `unsafe` (`unsafe_code = "forbid"`)
   - `.unwrap()`, `.expect()`, `panic!()`, `todo!()`, `unimplemented!()`, `dbg!()`
   - `println!()` / `eprintln!()` outside `crates/gf-cli/src/output.rs`
2. **Algebraic error handling**:
   - Exclusively use `Result<T, E>` or `gf_core::validation::Validation<T, E>`.
   - In tests (`#[test]`), return `Result<(), E>` and propagate with `?`.
3. **SRP Limits (Single Responsibility Principle)**:
   - Maximum **250 lines** per `.rs` file (enforced by `tests/architecture.rs`).
   - Maximum **50 lines** per function (`too-many-lines-threshold = 50`).
   - Maximum cognitive complexity of **10** (`cognitive-complexity-threshold = 10`).
   - Maximum **4 parameters** per function (`too-many-arguments-threshold = 4`).
   - Maximum **2 booleans** per struct (`max-struct-bools = 2`).
4. **Mandatory documentation**:
   - Every public item must have Rustdoc (`///`), including an `# Errors` section for every fallible public function returning `Result`.

---

## 3. Development Discipline & Anti-Cheat

- **Absolute ban** on `git commit --no-verify` or bypassing `lefthook`.
- **Absolute ban** on `#[allow(...)]` (`allow_attributes = "deny"`). Only `#[expect(..., reason = "...")]` is permitted for an explicit, documented architectural boundary (e.g. `crates/gf-cli/src/output.rs`).
- **TDD & Coverage**: maintain **>= 85%** line coverage (`task cov`) and verify mutations on every diff (`task mutate`).
- Before finishing any change, run `task check:full` and resolve 100% of diagnostics.

## Core Engineering Guardrails (Zero Technical Debt)

### Architectural & Code Discipline

- Respect **Functional Core, Imperative Shell**: isolate pure deterministic domain transformations from filesystem, network, and process side effects.
- Enforce **SRP** (single responsibility per file and callable), **DRY** (extract genuine structural duplicates instead of renaming variables cosmetically), **KISS** (flat control flow, guard clauses, no nested ternaries or Law of Demeter property trains), and **YAGNI** (no speculative barrel `export *` or single-implementation interfaces).
- Never silence or bypass static analysis: inline suppression comments, unjustified lint attributes, `TODO`/`FIXME` placeholders in production code, and `--no-verify` Git commits are strictly forbidden (`GF070`, `GF074`).
- Every automated test must assert real observable behavior or algebraic invariants (`GF076`); assertion-free smoke stubs and constant tautologies are blocked.

### Mandatory Verification Loop

1. Run `garde check --staged --format agent` before staging or committing changes and resolve 100% of reported violations at their root cause.
2. Never weaken thresholds in `garde-fou.toml` without explicit human authorization; `garde.lock` (`GF070`) and `AGENTS.md` (`garde sync`) seal project governance.
3. Write Conventional Commit headers (`<type>(<scope>): <imperative summary>`, `GF077`) that state what changed and why.

## Six-Domain Segregation Law (`GF060`–`GF066`)

### Strict Domain Responsibilities

- **`Code`**: pure business logic, state transitions, and semantic UI structure. Zero CSS-in-JS, inline `style=`, raw `#hex` colors, inline `<svg>`, `data:` URIs, or imports from `Scripts`.
- **`Scripts`**: standalone developer and CI automation (`scripts/`, `tools/`), subject to file/secret limits and mandatory automated test coverage (`GF065`).
- **`Forme`**: stylesheets and themes (`styles/`, `tokens/`). Primitive `#hex`/`px`/`oklch` values live exclusively inside token files; component stylesheets consume `var(--token)` without `!important` (`GF061`).
- **`Texte`**: pure plain-text `i18n` dictionaries (`locales/`), kept 100% key-symmetric across locales with zero HTML markup (`GF062`).
- **`Contenus`**: editorial Markdown/MDX (`content/`, `courses/`, `docs/`) as Single Source of Truth, free of raw HTML, hooks, or stylesheet imports (`GF063`).
- **`Asset`**: confined static media and sanitized SVGs (`assets/`, `public/`, `static/`) within `max_asset_bytes`, with zero broken links or unreferenced orphans (`GF064`).

## Rust Quality Standards (Edition 2024)

### Safety, Error Handling & Idioms

- Forbid `unsafe`, `.unwrap()`, `.expect()`, `panic!()`, `todo!()`, `unimplemented!()`, and `dbg!()` in both production modules and tests (`GF010`).
- Propagate recoverable failures algebraically via `Result<T, E>` (or applicative `Validation<T, E>`) using `?`, and document `# Errors` on every fallible public item.
- Prefer borrowed slices (`&str`, `&[T]`) over premature `.clone()`, deterministic `BTreeMap`/`BTreeSet` when output ordering matters, and small structs (`<= 2` booleans).
- Keep `cargo clippy --workspace --all-targets --all-features -- -D warnings` at zero warnings without `#[allow(...)]`.

## POSIX Shell & Bash Standards (`GF080`–`GF082`)

### Strict Mode, Quoting & Portability

- Enable `set -eu` in POSIX `#!/bin/sh` scripts and `set -euo pipefail` (or `set -eu` plus `set -o pipefail`) in `#!/bin/bash` scripts (`SH-STRICT-MODE`, `GF080`).
- Double-quote `$var`, `${var}`, and `$(cmd)` expansions in command arguments and `for x in ...` lists (`SH-SC2086`, `SH-SC2046`); scalar assignments `a=$b`, `case $a in`, `[[ ... ]]`, and `$(( ... ))` are word-split-safe.
- Separate scope declarations (`local`, `export`, `readonly`) from `$(cmd)` assignments so exit codes are never masked (`SH-SC2155`), guard recursive `rm` expansions with `${var:?}` (`SH-SC2115`), check `cd` failures (`SH-SC2164`), avoid `eval` (`SH-NO-EVAL`), and keep `#!/bin/sh` scripts 100% free of bashisms such as `[[ ... ]]`, `(( ... ))`, arrays, `function`, `source`, `<<<`, `${var//a/b}`, `local`, and unguarded `set -o pipefail` (`SH-SC3000`).
- Never use `# shellcheck disable=all` or `.shellcheckrc` global range disables (`GF070`, `GF081`); single-code `# shellcheck disable=SCxxxx -- <reason>` requires a `>= 10`-character justification, and `[shellcheck:...]` findings (`GF082`) must be fixed at their root cause.

## PowerShell Automation Standards (`GF080`–`GF082`)

### Strict Header, Null Safety & Secret Parameters

- Declare `Set-StrictMode -Version Latest` and `$ErrorActionPreference = 'Stop'` at the top of executable `.ps1` scripts (`PS-STRICT-HEADER`, `GF080`).
- Place `$null` on the left-hand side of equality comparisons (`$null -eq $items`, `$null -ne $cmd`) so array operands never trigger PowerShell collection filtering (`PS-NULL-LEFT`).
- Forbid `Invoke-Expression` / `iex` (`PS-NO-IEX`), type sensitive `param(...)` credentials (`$Password`, `$Secret`, `$ApiKey`, `$AccessToken`, `$PrivateKey`) as `[SecureString]` or `[PSCredential]` instead of `[string]` (`PS-PLAIN-SECRET-PARAM`), handle or log errors inside `catch` blocks (`PS-EMPTY-CATCH`), and avoid `$global:...` state (`PS-GLOBAL-VAR`).
- Never silence `PSScriptAnalyzer` via unjustified `[Diagnostics.CodeAnalysis.SuppressMessageAttribute(...)]` (requires `Justification` `>= 10` characters, `GF070`) or `ExcludeRules = @('*')` in `PSScriptAnalyzerSettings.psd1` (`GF081`), and resolve `[psscriptanalyzer:...]` diagnostics (`GF082`).

## YAML 1.2, Docker Compose & CI Standards (`GF080`–`GF082`)

### Canonical YAML 1.2 & Anchor Safety

- Eliminate duplicate mapping keys and conflicting `<<: [*a, *b]` merge keys (`YAML-DUPLICATE-KEY`); explicit keys in the child mapping may cleanly override inherited `<<: *base` defaults.
- Use lowercase `true` and `false` exclusively for booleans (`YAML-TRUTHY`, exempting root `on:` in GitHub Actions workflows), quote file-mode strings (`"0755"`) or write `0o755` (`YAML-IMPLICIT-OCTAL`), quote sexagesimal-looking scalars (`"22:22"`, `YAML-SEXAGESIMAL`), and bound `&anchor` / `*alias` depth (`<= 16`, `<= 2048` nodes, `YAML-ANCHOR-BOMB`).
- Never silence YAML, Compose, or workflow analyzers via unjustified `# yamllint disable`, `# dclint disable`, `# actionlint ignore`, or `# zizmor: ignore[...]` comments (`GF070`), nor weaken `.yamllint*`, `.dclintrc*`, or `zizmor.yml` (`GF081`).

## TOML & Manifest Reproducibility Standards (`GF080`–`GF082`)

### Table Clarity, Immutable Pins & Workspace Inheritance

- Group dotted keys and subtables contiguously without out-of-order table reopenings, and expand inline tables exceeding `4` keys into standard `[table]` sections (`TOML-CONFUSING-TABLE-REOPEN`).
- Never use wildcard `"*"` versions, `"latest"` tool pins in `mise.toml`, or `git` dependencies without an immutable `rev = "<sha>"` or release `tag` in `Cargo.toml` and `pyproject.toml` (`TOML-UNPINNED-GIT-OR-WILDCARD`).
